# DolphinDB — Label Propagation Challenge

Synchronous Label Propagation（DolphinDB 编程挑战）。读入无向图 CSV，运行同步标签
传播直至收敛，输出按 node_id 升序的 `output.csv`。无第三方依赖，仅 C++20 标准库 +
OpenMP。

## 构建与运行

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
./build/label_propagation <input.csv>   # 结果写入当前目录 output.csv 后立即退出
```

设置 `LP_TIMING=1` 可向 stderr 输出各阶段耗时。

## 架构

- **读入**：整个文件 `mmap` + `MADV_WILLNEED`，页错误与并行解析自然重叠，无独立 I/O 阶段
- **预扫描**：按字节区间并行走行，数出行数（确定行号基准）并提取每行 id span 与数值，
  同时判定"行 id 是否恰为行号的规范十进制形式"（`rowCanon` 表）
- **解析**：每线程独立解析自己的行区间
  - 数值邻居 id：`val < R 且 rowCanon[val] == id位数` 时直接命中全局行号（单字节
    比较且已预取，稠密数值文件 ~100% 命中）；未命中走数值 interner（`(值,长度)` 为
    键、16 字节槽位、无碰撞，前导零视为不同 id）；非数字走字符串 interner
  - 邻居解析为 4 级环形流水线：提前解析后续 3 个 id 并预取其探测槽位，隐藏内存延迟
  - 各线程解析完成后立即把自己的行 id 插入分片全局表（与慢线程的解析重叠）
- **resolve + CSR 融合**：各线程把局部 id 解析为全局行号后直接顺序拷贝自己的邻接段
  （按行序 CSR，无随机 scatter）；仅作为邻居出现、无行的 id 分配行号之后的附加 id
- **标签**：全局去重后按字典序排名，平票规则退化为"取最小整数 rank"
- **迭代**：活跃前沿（active-frontier）——前几轮全量重算（动态调度适配异构核）；
  变更数降到 N/4 以下后，每轮只重算"邻居上一轮发生变化的节点"（同步语义通过
  nxt 缓冲 + 轮末提交保持）
- **输出**：已有序检测（数值 id 常见且有序则跳过排序）→ 数值 LSD 基数排序 /
  字符串 std::sort 回退 → 并行拼装单个未初始化缓冲 → 一次 fwrite

## 优化历程

基准数据：big.csv —— 2,000,000 节点 / 885 MB / 1.19 亿边端点（WSL2，14 线程，warm cache）。

| 版本 | 端到端 | 当时瓶颈与对策 |
|---|---|---|
| v1 基线 | 18.1s | 单线程解析邻居 ID（1.19 亿次哈希表查找）占 84%（15.6s） |
| v2 | 4.1s | 每线程本地 interner 解析 + 分片锁并行合并；mmap 免独立读入 |
| v3 | 2.9s | 串行 memchr 行扫描并行化；输出排序改基数 + 有序检测；并行拼装输出。教训：SoA interner 命中路径双随机访问反而更慢，回退 AoS |
| v4 | 2.7s | 全局 ID 直接采用行号 → CSR 从随机 scatter 变纯顺序拷贝；去掉行号数组；解析循环加预取 |
| v5 | 1.6s | 数值 id 专用 16B 注入式键 interner（无哈希碰撞/无 memcmp/槽位减半）；`make_unique_for_overwrite` 免 476MB 清零 |
| v6 | 1.57s | 解析流水线加深到 3 级预取；迭代全量轮恢复直接寻址 + `cur[adj[j+4]]` gather 预取 |
| v7 | 1.45s | 预取环形队列加深到 4 级（免搬移循环索引）；numTab 按 6 倍行数预分配避免 rehash；resolve 阶段预取；`MADV_WILLNEED`/`MADV_HUGEPAGE`；parse 0.75→0.39s |
| v8 | 0.96s | ①预扫描：并行数行 + 提取每行 id span/数值（顺带解决行号基准）；②**标准十进制快路径**：行 id 恰为 `行号` 的规范十进制时（稠密数值文件的常态），邻居解析为数值后仅比一个预取好的字节（`rowCanon[val]==位数`）即得全局 ID——数学上无碰撞（纯数字+无前导零+值相等+长度为最小位数 ⇔ 字符串相等），消除几乎全部哈希探测与 memcmp；③行 ID 插入融入解析 region；④resolve 与 CSR 拷贝融合。resolve+csr 0.27→0.05s，parse 0.39→0.24s，内存 2.9→2.3GB |
| v9 | **0.91s** | 输出缓冲免零初始化；迭代 gather 预取距离调至 j+24；全量轮动态调度（适配 P/E 混合核） |

最终：14 线程中位 **0.91s**；8 线程（评测机同构）1.13-1.43s；冷缓存 8 线程 1.62s；5M 节点/2.3GB 大盘 8 线程 5-6s；峰值内存 2.3GB。剩余成本为必要开销：mmap 页触碰、两轮强制全量迭代（内存带宽墙）、输出写出。

### 定量归因（8 线程视角）

- 迭代阶段（0.24s/轮 × 2 轮）：邻接表 476MB 顺序读 + cur 随机 gather，已达 VM 内存带宽极限（预取距离 4/12/24 与调度策略实测均在噪声内）；评测机裸金属 DDR 带宽更高，预期更快
- 解析阶段 0.27s：全文件必须触碰一遍 + 每邻居一次预取好的单字节比较
- 前沿模式保证收敛尾部只重算受影响节点，高迭代数数据不退化

## 正确性验证

- 官方样例比对
- 8 组随机图与 Python 参考实现（按规格逐字实现）交叉验证：覆盖稀疏/稠密、多社区、
  纯字符串/混合/前导零 ID、单标签、高标签数；200k 节点全量交叉验证
- 边界用例：CRLF、UTF-8 BOM、引号字段（含带空格标签）、单节点、邻居前向引用、
  重复邻居、800 种标签、乱序行
- 终审边界用例：空文件、仅表头、末行无换行符、19 位超长数字 ID（回退字符串路径）、
  零基编号 ID、双跑输出逐字节一致（确定性）、空行与 `\r` 杂行混入
  （专项验证预扫描与解析的行对齐不变量——快路径正确性的根基）
- 动态分析：ASan + UBSan 于 6 组代表性输入零报告；`-Wall -Wextra -Wpedantic`
  零警告；干净目录从零 CMake 构建通过（模拟评测机流程）

## 已知边界

- 同步标签传播在个别结构（如网格棋盘构型）下会周期 2 振荡不收敛——这是算法本身
  的性质（参考实现同样不停），规格保证评测数据收敛，程序行为与规格一致
- 行数上限 2^30（约 10.7 亿行，对应 200GB+ 输入）——超出后 ID 位标记编码冲突，
  远超现实规模
- 重复 node_id（违反规格"唯一"假设）会优雅降级（输出重复行）而非报错

## 调试中修过的关键 bug（留作记录）

1. 邻居列表最后一个 id 把 `]` 一起解析进去，产生带 `]` 的幽灵节点（官方样例因
   幽灵票恰好也投 black 而侥幸通过）
2. `rowOff` 缺末尾哨兵，最后一行度数读到越界垃圾值 → 大数据段错误
3. 输出表头长度按 19 计算（实际 20），首行数据覆盖表头换行符
4. `Interner::intern` 在 `grow()` 释放旧表后通过悬空引用 `return e.id`（UAF，
   -O1/ASAN 布局侥幸通过，-O3 稳定崩溃）
5. 输出偏移前缀按文件序累加、写入却按排序位置索引——数值 id 排序为恒等排列时
   不触发，字符串 id 立即互相覆盖
6. 预取循环中当前/下一个字符串哈希复用同一变量，用下一个的哈希 intern 当前字符串
